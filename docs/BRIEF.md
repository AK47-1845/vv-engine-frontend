# Genuity Verify: Product Brief

## Confirmed With The User

- Workspace deliverable: `claude bro` inside the existing `karthik` folder.
- Audience: LTTS CTO and stakeholders, then validation engineers and independent reviewers.
- Inputs: the user requested both uploaded/API evaluation and live robot/simulator integration, with broad advanced coverage. No hardware endpoint, credentials, deployment target, or validated calibration dataset was supplied.
- Visual direction, verbatim selection: "Precision engineering console".
- Option description shown: "Light, crisp, data-dense. Dark simulation workspace, clear evidence, restrained technical typography."
- The user prioritizes a fully working backend and frontend, documentation, source research, and durable context over speed.

## Interview Application

Scrollcraft's interview-first and screenshot-verification discipline informs this build. Its eight-question landing-page/scroll-film workflow is not the product format: this is an engineering application, not a promotional site. No paid asset generation is authorized or required.

## Product Journey

1. Understand the current assurance posture and unresolved evidence gaps.
2. Select a policy, embodiment, dataset, and immutable gate profile.
3. Evaluate a trace or run a reproducible stress experiment.
4. Inspect the failure in trajectory replay and per-layer measurements.
5. Review evidence and make a role-authorized release decision.
6. Export an independently checkable evidence package.

The memorable interaction is selecting a failed gate and seeing the exact associated trace interval, measurement, threshold, and evidence source together.

## Scope And Truthfulness

- Implement useful evaluation, provenance, evidence, governance, and bounded integration contracts.
- Never present synthetic demonstrations as physical robot measurements.
- Missing required evidence must not produce a passing gate.
- Proxy metrics are not contact-dynamics proofs, formal guarantees, or automatic certification.
- Live middleware is supervisory. It must not claim to replace certified safety controllers or directly actuate equipment.
- Regulations and standards require dated, source-linked mappings with explicit applicability and human review.
- A deployable candidate still needs security review, hardware validation, calibrated thresholds, operational qualification, and assessor acceptance before safety-critical production use.
